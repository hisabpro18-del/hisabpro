# HisabPro Android app

The Android app is the **shop owner's ledger (khata) app**. Only the shop **owner** can sign in (staff get a polite
"this app is for the shop owner" screen). It is not a POS: selling, staff, HR and full settings stay on the web and the
Windows app. The home screen shows the shop's name and:

| Button | What it does |
|---|---|
| **Payment** (ادائیگی) | Money paid out — to a vendor (their balance goes down) or as an expense (bill, rent …); from cash or a bank account |
| **Receipt** (وصولی) | Money received — from a customer (their udhaar goes down; WhatsApp thank-you, printed slip) or other income |
| **Reports** (رپورٹس) | Today / yesterday / week / month: sales, profit, expenses, purchases, money in and out, cash & bank, to receive, to pay, low stock |
| **All Accounts** (تمام کھاتے) | Every customer and vendor with balance; tap one for the full khata, receipt/payment, reminder, promise, statement, call |
| **Stock** (اسٹاک) | Every product with stock, price and cost; low / out of stock filters; search or camera scan; stock value |
| **Vendor Reports** (سپلائر رپورٹ) | Per vendor for the period: bought, paid, still owed |
| **Reminders** (یاد دہانی) | Promises due today / late / upcoming and everyone who owes — WhatsApp or SMS reminder, new promise, receive |

Phone extras: **Bluetooth slip printing** (58 / 80 mm thermal printers; the slip is sent as a picture so Urdu prints),
**Android printing** for statements (*Save as PDF* to share), the **share sheet** for files, **WhatsApp** opens the
WhatsApp app, an **offline page** (English / Urdu). Settings (gear on the home screen): language, night mode, printer,
app version, sign out.

It needs internet. Offline selling stays with the Windows app at the counter.

## 1. How it works

```
 Android phone ── HisabPro app (Capacitor 8 WebView) ──HTTPS──► https://hisabpro-2r1x.onrender.com (same web app)
                    │  user agent ends with "HisabProApp/1.0"
                    │  window.Capacitor injected by the app
                    ├─ HpNative (our plugin, Java)     Bluetooth ESC/POS printing · Android print dialog · share files
                    ├─ CapacitorBarcodeScanner          camera scanning (Google ML Kit)
                    └─ App                              installed version (for update notices)
```

- `mobile/capacitor.config.json` → `server.url` makes the app load the live server. **Screen and feature changes reach
  the app with every normal web deploy.** A new APK is needed only when the native part changes (plugins, permissions,
  icon, server address).
- The web app knows it runs inside the app from the user agent (`HisabProApp/`), see `public/js/core/native.js`
  (`HP.native.isApp()`, `HP.mobile.on()`). In phone mode the router shows **only** the `/m…` screens (pages marked
  `mobile: true`), the shell is a simple phone frame (back arrow, title, language, settings), home is `/m`, and
  `app.js` lets only the `OWNER` role in. The full web app never shows the `/m…` screens.
- Preview the phone screens in a normal browser: DevTools → phone size, then in the console
  `localStorage.setItem('hp.mobileMode','1')` and reload (`removeItem` to go back).
- Native calls use `Capacitor.nativePromise(plugin, method, options)` because the remote page does not load
  Capacitor's JavaScript packages.
- Every phone screen uses the existing APIs (payments, expenses, khata receive, parties, ledger, reports, catalog,
  promises); the only new endpoint is `GET /api/reports/vendors` (per-vendor bought / returned / paid / owed).
- On the web and in the Windows app all of this is inert.

### Receipt printing in detail

1. `HP.ui.print()` in the app hands the print area to `HP.native.print()`.
2. Thermal receipts (`.receipt.w58` / `.w80`) go to the Bluetooth printer chosen on this phone (asked once; saved in the
   phone's browser storage). Anything else opens Android's print dialog.
3. Each receipt copy is redrawn as an SVG picture at the printer's width — **384 dots** for 58 mm paper, **576** for
   80 mm — turned black-and-white, and encoded as ESC/POS `GS v 0` raster bands, with a paper feed and a cut after each
   copy (printers without a cutter ignore the cut).
4. `HpNative.print` opens a Bluetooth Classic (SPP) socket to the paired printer and sends the bytes in 512-byte pieces
   with short pauses (small printer buffers).

Supported printers: most 58 / 80 mm **Bluetooth Classic ESC/POS** printers. **Not supported**: Bluetooth Low Energy-only
printers and printers that do not understand `GS v 0` raster images (rare).

## 3. Build the APK

### 3.1 One-time: build tools on the build computer

The project uses **Capacitor 8**, **Gradle 8.14.3**, **Android Gradle Plugin 8.13**, **Java 21**, **Android SDK 36**
(minimum Android 7 / API 24).

Easiest: install **Android Studio** (it includes Java 21 and the SDK manager), open it once, and in *SDK Manager*
install *Android 16 (API 36)* SDK Platform, *Build-Tools 36*, *Platform-Tools*.

Or on the command line (macOS with Homebrew):
```bash
brew install openjdk@21
export JAVA_HOME="$(brew --prefix openjdk@21)/libexec/openjdk.jdk/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
sdkmanager "platforms;android-36" "build-tools;36.0.0" "platform-tools"
```
Then tell the project where the SDK is (this file is git-ignored):
```bash
echo "sdk.dir=$HOME/Library/Android/sdk" > mobile/android/local.properties
```

### 3.2 Debug build (for testing on your own phone)

```bash
cd mobile
npm install                 # first time only
npm run debug               # cap sync + gradlew assembleDebug
# → mobile/android/app/build/outputs/apk/debug/app-debug.apk
adb install -r android/app/build/outputs/apk/debug/app-debug.apk   # phone with USB debugging on
```
Or `npm run open` and press ▶ in Android Studio. Debug builds are signed with a throw-away debug key: fine for testing,
**never hand them to shops** (a later release could not install over them).

### 3.3 The release signing key (create once, keep for ever)

Every APK you give shops must be signed with the **same key**, or Android refuses to install the update over the
installed app. **Losing the key means every shop has to uninstall and reinstall.**

```bash
keytool -genkeypair -v -keystore ~/hisabpro-keys/hisabpro-release.jks -alias hisabpro \
  -keyalg RSA -keysize 4096 -validity 10000
```
Then create `mobile/android/keystore.properties` (git-ignored — never commit it or the `.jks`):
```properties
storeFile=/Users/<you>/hisabpro-keys/hisabpro-release.jks
storePassword=…
keyAlias=hisabpro
keyPassword=…
```
Keep the `.jks` file and both passwords in **two safe places** (password manager + an offline copy). Whoever holds them
can publish updates that shops' phones will accept.

### 3.4 Release build

1. Raise the version in `mobile/android/app/build.gradle`: `versionCode` (whole number, +1 every release) and
   `versionName` (e.g. `1.0.1`).
2. Build:
   ```bash
   cd mobile && npm run release
   # → mobile/android/app/build/outputs/apk/release/app-release.apk (signed with your key)
   ```
3. Test it on a phone (§6) before giving it out.

## 4. Release an APK

```bash
VER=1.0.0
cp mobile/android/app/build/outputs/apk/release/app-release.apk /tmp/HisabPro-$VER.apk
gh release create android-v$VER --repo hisabpro18-del/hisabpro --target main \
  --title "HisabPro Android $VER" --notes "What changed for shops" /tmp/HisabPro-$VER.apk
```
Then tell the installed apps about it — edit `mobile/release.json`:
```json
{ "android": { "version": "1.0.0", "versionCode": 1,
  "url": "https://github.com/hisabpro18-del/hisabpro/releases/download/android-v1.0.0/HisabPro-1.0.0.apk",
  "notes": "What changed, in plain words" } }
```
commit and push (Render deploys it). Apps with a lower `versionCode` show a one-time notice and **Settings → Phone app
→ Download update** (it downloads the APK; opening it installs over the old app, keeping logins and settings).

The Windows app's releases use tags `v…`; Android uses `android-v…` so the two never mix.

### Giving the app to a shop

Send the release link or the APK on WhatsApp. On the phone: open it → Android asks to **allow installing from this
source** (Chrome / WhatsApp / Files) → allow → Install. Google Play Protect may warn about an app from outside the Play
Store → *Install anyway*. Then sign in with the user's usual HisabPro email and password.

## 5. Using it in the shop

- **Sign in** with the owner's HisabPro email and password (staff accounts are refused on the phone).
- **Printer**: switch the printer on → Android *Settings → Bluetooth* → pair it (PIN usually `0000` or `1234`) → in
  HisabPro tap the **gear** on the home screen → *Choose printer* (or simply tap *Print slip* after a payment or
  receipt: it asks once) → choose 58 or 80 mm → *Test print*. Android 12+ asks once to allow **Nearby devices**: allow.
- **Scanning**: the camera button in **Stock** finds a product by its barcode. Android asks once for the camera.
- **Statements**: All Accounts → a customer → *Statement* → Android print → *Save as PDF* → share on WhatsApp.
- **Back button / arrow**: closes an open dialog first, then goes back a screen.

## 7. Troubleshooting

| Symptom | Fix |
|---|---|
| Gradle: "Unsupported class file major version" / needs Java 21 | `JAVA_HOME` must point to Java 21 |
| "SDK location not found" | Create `mobile/android/local.properties` with `sdk.dir=…` |
| Update APK will not install ("App not installed", "package conflicts") | It was signed with a different key (e.g. a debug build was installed). Uninstall once, install the release |
| "Could not print … read failed" | Printer off, out of range, paired with another phone, or wrong PIN. Unpair/pair again |
| Printer prints nothing or garbage | Printer is not ESC/POS raster-compatible or is BLE-only. Try *Android print* (with the printer maker's Android print service) or another printer |
| Receipt too faint | Raise the printer's density (its own settings); the picture is pure black and white |
| Scanner closes at once | Camera permission denied → Android Settings → Apps → HisabPro → Permissions → Camera |
| Blank / old-looking pages | Update *Android System WebView* and *Chrome* from the Play Store |
| Shows "No internet connection" | No connection or the server is down; check `https://hisabpro-2r1x.onrender.com/healthz` |

## 8. Later

- **Google Play**: needs a Google Play developer account (USD 25 once), an `.aab` (`cd mobile/android && ./gradlew
  bundleRelease`), Play App Signing (upload key = the key above), store listing, privacy policy and the Data safety form.
  Play-installed apps update through the Play Store; keep `release.json` for side-loaded installs.
- **Own domain**: change `server.url` in `capacitor.config.json` (and `www/error.html`), then release a new APK. Keep
  the onrender.com address working until every phone has updated.
- **iPhone**: Capacitor can add iOS (`npx cap add ios`) — needs a Mac with Xcode and an Apple Developer account
  (USD 99/year). The Bluetooth plugin would need an iOS (Swift) version; iPhones only talk to BLE or MFi printers.
- **Offline on Android**: not planned — it would need the selling, khata and sync logic rebuilt to run on the phone.
